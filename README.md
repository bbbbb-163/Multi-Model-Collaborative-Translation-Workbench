# 模型工作台

支持 Mstar 统一模型服务的多模型工作空间。左侧任务，中央统一对话，右侧可收起的模型抽屉。右侧默认进入 **Mstar**，展示管理员上架且当前密钥获授权的模型；**我的模型**保留用户自行接入服务的功能。没有内置演示模型或伪造生成结果。

## 启动

需要 **Node.js 24 或更新版本**。Windows 双击根目录的 **启动工作台.cmd**，会安装依赖、构建、启动并打开浏览器。保持启动窗口打开；关闭它会停止本机服务。

也可在项目目录运行：

```powershell
npm install --registry=https://registry.npmjs.org
npm run build
npm start
```

访问 **http://127.0.0.1:3210**；管理员后台是 **http://127.0.0.1:3210/admin**。开发模式使用 `npm run dev`，前后端共用一个地址。

首次启动时，终端会显示一次性管理员初始化码，也保存在数据目录的 `admin-setup.txt`。在 `/admin` 输入初始化码并设置至少 12 位的管理员密码；成功后初始化码文件自动删除，不提供公开注册或默认密码。已有本机连接、任务和附件归管理员自己的工作空间，不会交给第一个登录的用户。

管理员登录后，可在后台「账号安全」修改自己的登录密码：输入当前密码、新密码及确认新密码，新密码需为 12–200 位且与当前密码不同。修改成功后，所有管理员后台及管理员工作空间会话立即失效，使用新密码重新登录；普通用户的 Mstar 密钥和登录不受影响。

**工作台与后台会话独立。** 登录管理员后台不会自动登录工作台。用户退出、密钥过期或停用后，工作台回到密钥登录页，即使同一浏览器仍登录后台也不会切换成管理员；退出后台也不退出用户工作台。需要访问迁移前的管理员个人连接和任务时，在后台明确点击「管理员工作空间」创建独立的工作台会话；已有用户登录时会拒绝切换，避免替换用户身份。退出管理员工作空间只清除该工作台会话，后台仍可继续管理。

## 管理员接入、测试与分发

1. 在后台「模型连接」填写 **API 地址 + API Key**，连接并自动获取模型列表。名称、协议、手动模型 ID 和私有能力定义放在折叠的高级设置内；沿用用户自接模型的适配逻辑。
2. 在「模型上架」选择连接及模型，填写给用户展示的名称，并勾选开放的能力。保存草稿后逐项测试能力；测试会真实调用供应商，可能消耗额度，需要文件输入的能力可上传测试附件。
3. 所有开放能力测试通过后，点击「上架到 Mstar」。连接配置变更会清除相关模型的测试结果并下架，必须重新测试；获取模型目录本身不会当作已验证生成能力。
4. 在「分发密钥」生成独立的 **Mstar 密钥**，按具体模型勾选授权，可设置有效期。完整密钥只在生成时显示一次，后端只保存校验摘要；请在离开页面前复制保存并分发。
5. 用户在工作台首页凭 Mstar 密钥登录，只看到已上架且获得授权的模型。后台可以调整授权、停用或撤销密钥。调整授权、下架或修改模型会中止相关工作台运行；远端已经创建的生成任务是否继续或收费，取决于供应商。

Mstar 密钥与供应商 API Key 完全分离。用户端不提供 Mstar 连接编辑入口；上游地址、凭据、协议、真实模型 ID、私有请求模板和远端任务编号不作为 Mstar 配置下发。模型目录、任务保存和实际调用都在服务端检查权限；历史产出保留，已撤销权限的模型无法继续调用。Mstar 请求不接受用户提交的接口参数覆盖。

## 简洁的操作流程

1. 使用分发密钥登录，在右侧「Mstar」选择模型加入当前任务。需要自行接入时，切换「我的模型」并添加连接，填 API URL 和 API Key。
2. 自接连接可展开下拉列表，勾选具体模型加入任务；同一 Key 下的多个模型可同时加入，也可以与 Mstar 模型一起工作。一个任务最多 8 个成员。
3. 在输入框的「调用方式」中选择如何执行：

主输入区只保留附件、调用方式及相应的模型选择。系统根据任务描述、附件和模型已启用的能力自动匹配调用方式；用户无需选择能力分类，也不需要填写 JSON 接口参数。模型列表保留能力标签。

| 方式     | 操作与行为                                                                                                                                                                         |
| -------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 单独调用 | 在旁边选择本次调用的具体成员。系统自动匹配其已启用的能力，只运行这个模型，不委派给其他成员。                                                                                       |
| 自动协作 | 支持对话的成员并行完成本次请求，按需调用图像/视频/语音等成员；完成后汇报并结束，不自动开始下一轮讨论。多个对话成员由协调成员汇总已有成果。没有对话成员时，所选生成模型各执行一次。 |
| 顺序执行 | 同页展开步骤列表。选择每步模型和可选指令，可增删或上下移动。根据本步指令与实际输入自动匹配能力，默认传递上一步真实产出，出错或停止后不执行后续步骤。                               |

例如，右侧勾选文生图模型 A 与图生视频模型 B，选择「顺序执行」，保留 A→B 两步。给 A 描述要生成的图片，给 B 补充「让参考图中的树叶随风移动，生成视频」。发送任务后，A 的真实图片会先保存到本机，再以文件内容作为 B 的参考输入，不需要手动选择能力或下载再上传。多能力模型的要求不明确时，会提示补充任务描述。

每步可展开修改输入来源（上一步、本次原始输入、所有前序产出）。指令留空时使用本次消息；支持 `{{task}}`（本次消息）、`{{input}}`（前序文字）。步骤设置不提供 JSON 接口参数编辑框，普通执行使用内部默认配置。

如果模型明确不支持部分输入，工作台会先在对话中说明限制，并提供「是，仅用…开始」「否，暂不开始」。例如只接受图片的图生视频模型遇到图片和文字时，确认后只发送图片，不发送文字；取消时不调用该模型，原始输入仍保留在对话中。缺少必需输入时直接提示补充，并建议添加多个模型协作。确认支持刷新与跨页签同步，停止任务、撤销权限或重启后失效，重复点击不会重复生成。

所有文字、讨论、代码文件、图片、可播放音频/视频和错误均保存在同一个任务消息流中。支持附件上传、复制文字/代码、下载产出、导出 Markdown/JSON、重命名与删除任务。运行时刷新或切换任务不会停止后端执行。

## 接口支持与实际边界

协议与能力分离。当前提供以下执行适配器，后续能力无需增加新页面：

| 协议           | 已实现的接口                                                                                                                                                               |
| -------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| OpenAI 兼容    | `/models`、流式 `/chat/completions`、工具调用、`/images/generations` 与 `/images/edits`、`/videos` 创建/查询/下载、`/audio/speech`、`/audio/transcriptions`、`/embeddings` |
| OpenAI 原生    | Responses 流式文本/编码与工具调用；媒体通过上述对应接口                                                                                                                    |
| Anthropic 原生 | `/models` 与 Messages 流式、视觉输入、工具调用                                                                                                                             |
| Gemini 原生    | 模型发现、generateContent 流式对话/工具与多模态文件输出、图像/语音/转写、Imagen predict、Veo 异步生成（包括参考图）、embedContent                                          |
| 私有协议       | 同页高级设置的自定义同步/异步 HTTP 能力，见下方                                                                                                                            |

针对你选择的两家服务：

- **火山方舟**：填写 `https://ark.cn-beijing.volces.com/api/v3`（套餐请使用该套餐自己的地址和 Key）。已适配 Seedream 的 JSON 参考图请求，以及 Seedance 的 `/contents/generations/tasks` 创建、查询和视频下载；不是 OpenAI `/videos` 请求。已下线的 `Shutdown` 模型不加入发现结果。按量与套餐的模型目录和权限可能不同；不返回目录时请补充控制台 Model ID 或 Endpoint ID。
- **NVIDIA NIM**：对话/文本向量填写 `https://integrate.api.nvidia.com/v1`，按上游目录选模型。文本向量默认 `input_type=query`，索引场景可在接口参数设为 `passage`。NVIDIA 的图像模型是独立端点，可填写模型官方文档中的完整 URL，例如 `https://ai.api.nvidia.com/v1/genai/black-forest-labs/flux.1-dev`；工作台从完整路径解析具体模型，并处理 artifact base64 与 NVIDIA 202/request ID 轮询。解析出模型不代表已验证 Key。不同 NIM 模型的额外参数依照其官方接口文档；不把所有 NIM 端点当作聊天接口。

官方参考：[方舟视频任务 SDK](https://github.com/volcengine/volcengine-python-sdk/blob/master/volcenginesdkarkruntime/resources/content_generation/tasks.py)、[NVIDIA 模型发现](https://docs.nvidia.com/nim-operator/latest/guardrail.html)、[NVIDIA FLUX 接口](https://docs.api.nvidia.com/nim/reference/black-forest-labs-flux_1-dev-infer)、[NVIDIA 向量接口](https://docs.api.nvidia.com/nim/reference/nvidia-llama-nemotron-embed-vl-1b-v2-infer)。

自动检测官方域名；兼容服务默认使用 Chat Completions。地址中明确带 `/messages` 或 `/responses` 时也会识别。代理的原生协议可在高级设置手动指定。可填写基础地址或完整常用接口地址。管理员连接本机 Ollama 可使用兼容地址 `http://localhost:11434/v1`；普通分发密钥的自接服务只能访问公网地址，避免把服务器本机和内网服务暴露给用户。

**只填 URL 与 Key 能否完成接入，取决于上游是否提供模型列表和已支持的接口规范。** 各平台媒体 API 并非统一标准，不能仅凭一个 Key 自动猜出所有私有请求格式。服务无 `/models` 时，可在高级设置补充准确模型 ID；私有媒体路径、请求格式和结果字段由管理员用自定义能力接入。模型能力以服务声明为优先，缺少元数据时根据名称匹配；用户模型列表仅展示模型名称和能力标签，能力来源可在连接管理中查看，管理员仍可配置与测试能力。发现模型不等于已验证全部能力。使用不支持的能力会显示真实接口错误。

输入限制与输出能力分开判断，不会仅凭「图生视频」名称认定模型不支持文字。工作台读取上游 `input_modalities` / `architecture.input_modalities` 或按能力声明的 `input_constraints`，并使用已知适配器及明确的自定义请求模板规则；未知限制保持未知。管理员可在后台「模型连接 → 管理连接 → 对应模型 → 输入限制（可选）」补充输入限制 JSON，例如 `{"video":{"accepted":["image"],"required":["image"]}}` 表示视频能力只接收图片且必须有图片。支持 `text`、`image`、`audio`、`video`、`file`，`required` 可省略；此配置不开放给用户，修改后仍需重新测试并上架。

自动协作需要模型支持工具调用，才可以自主委派。普通对话模型仍能参加并行工作、讨论与汇总；对于明确拒绝 tools/function 参数的接口，会退回普通对话。代码模型可生成代码和可下载文件；当前未提供执行主机命令、联网浏览器或自动运行项目的工具。

步骤链可以确定执行顺序，但自动协作中的分工和调用行为取决于模型实际的工具使用能力。自动协作执行本次工作、按需使用工具并汇报，完成后等待新的用户消息，不主动循环讨论；已有任务的旧持续协作及多轮设置在执行时自动归一。多个对话成员的最终汇总只读取已有成果，不提供委派、生成或保存工具。执行中仍可停止或切换调用方式，成员失败会保留错误并在汇总中说明。每个模型的单次调用最多连续 5 个工具步骤，委派深度最多 2 层并阻止循环；各模式保留内部请求预算。成员上限 8、工作流步骤上限 12。

停止会中止本机网络等待和后续执行；远端已经创建的媒体生成任务是否收费或继续执行，由服务决定。单次媒体轮询最多 20 分钟，各调用方式整体运行最多 25 分钟；重启后把未结束的运行标记为中断。错误时已产出文件会保留，可重新发送消息继续。

## 扩展私有能力

管理员在后台连接高级设置的「扩展能力定义」填写数组，再在该连接的模型能力中勾选扩展项。用户端不提供这些配置入口。例如：

```json
[
  {
    "id": "image-to-video",
    "label": "图生视频",
    "path": "/my/video/create",
    "body": {
      "model": "{{model}}",
      "prompt": "{{prompt}}",
      "image": "{{image_base64}}"
    },
    "output": "video",
    "poll": {
      "path": "/my/video/jobs/{{id}}",
      "statusPath": "status",
      "complete": "completed",
      "failed": "failed",
      "resultPath": "output.url"
    }
  }
]
```

请按实际服务文档替换路径和字段。首次创建响应需要有 `id` 或 `name`，轮询使用 GET。`statusPath` / `resultPath` 使用点分路径，数组可写 `data.0.url`。同步能力省略 `poll`，在顶层指定 `resultPath`。`method` 默认 POST，可设 GET。`output` 可为 `text`、`json`、`image`、`video`、`audio`。

模板支持 `{{model}}`、`{{prompt}}`、`{{files}}`（含 name/mime/base64 的数组）、`{{image_base64}}`、`{{audio_base64}}`、`{{video_base64}}` 和接口参数中的字段。完整占位符保留数组/对象类型。媒体结果支持 URL、`b64_json`、`bytesBase64Encoded`、`inlineData`。请求使用该连接的鉴权方式。扩展定义只执行相对 API 路径，不执行 JS 或主机命令。

## 本地数据

- `.data/workbench.sqlite`：连接、上架模型、密钥授权与摘要、会话摘要、管理员密码校验值、任务、消息、文件索引，SQLite WAL 持久化。
- `.data/files/`：上传和生成的真实文件。单上传文件最多 40 MB，每条消息最多 10 个；远端媒体下载最多 200 MB。
- `.data/vault.key`：本机随机加密密钥，API Key 使用 AES-256-GCM 加密后入库。浏览器只拿到 Key 尾号，不存完整 Key。
- 整个 `.data/` 被 Git 忽略。备份时需完整备份此目录；拥有该目录全部文件的本机用户能够解密凭据，这不是硬件或操作系统保险库。
- 默认只绑定 `127.0.0.1`。管理员认证独立于用户密钥认证，会话使用 HttpOnly、SameSite=Strict Cookie；HTTPS 部署启用 Secure。接口和附件要求登录，任务、文件和个人连接按密钥隔离；同一密钥的持有者共享该工作空间。
- 不启用跨站访问。上线生产使用 CSP；浏览器不存储完整上游 Key 或登录密钥。登录有限流，用户自接请求阻止私网、环回和元数据地址，并在连接使用的 DNS 解析处检查地址，下载重定向逐跳检查。
- 任务导出不包含 API Key。Markdown 中的附件链接指向本机服务；跨设备归档还需另行保留附件文件。

可通过 `PORT` 更改端口，通过 `WORKBENCH_DATA` 指定独立数据目录。模型请求由 Node 服务端发送到所填上游。用户自接公网请求使用独立的受限网络连接器；管理员接入允许明确配置的本地服务。

## 集中部署

**已有阿里云生产环境的 Git 管理、Gitee Webhook 自动部署与回滚，请按 [自动部署手册](deploy/GITEE_AUTO_DEPLOY.md) 操作。** `https://mstar.chat` 已经初始化，生产数据保留在 `/opt/mstar/runtime/data`。原始首次安装记录见 [DEPLOYMENT.md](DEPLOYMENT.md)，不要在现有服务器重复初始化。发布包不包含本机 `.data` 或凭据。

安全审查、已修复问题、默认资源边界及上线前剩余事项见 [SECURITY_REVIEW.md](SECURITY_REVIEW.md)。默认每个工作空间文件限额 1024 MiB、并行运行任务 3 个，服务总运行任务 24 个；可通过 `WORKBENCH_MAX_STORAGE_MB`、`WORKBENCH_MAX_RUNS_PER_OWNER`、`WORKBENCH_MAX_TOTAL_RUNS` 设置正整数。这些限制不会自动删除已有文件。

上传临时落盘、失败批次清理，目录查询及消息订阅均有并发边界。开发模式只允许本机监听，文件服务拒绝数据目录、数据库、初始化码及凭据。`.env.*` 默认不进入 Git（示例文件除外）。HTTPS 反向代理后可按实际拓扑设置 `WORKBENCH_TRUST_PROXY=loopback` 或明确的代理 IP/CIDR；默认不相信转发 IP，不能配置为信任全部来源。代理必须覆盖客户端传入的转发头。

对外提供 Mstar 时，由你保管并运行服务端，用户通过浏览器访问。**不要将生产 `.data`、数据库、`vault.key`、管理员密码或包含凭据的环境文件分发给用户。** 拥有服务器文件和运行权限的人能够解密上游凭据；浏览器隔离不能保护已交给用户的服务器文件。

在 HTTPS 反向代理后运行，设置 `WORKBENCH_ORIGIN` 为唯一公开地址，例如 `https://work.example.com`。同机代理可以继续使用默认环回监听；需要容器或其他监听地址时，额外设置 `WORKBENCH_HOST`。非环回监听没有 HTTPS 的公开地址配置时会拒绝启动。代理需保留 Host，转发 `/api`、静态页面和 `/admin`，关闭 SSE 缓冲，并为媒体和长请求设置足够的超时及上传大小。应用不信任客户端传入的转发头，也不启用通配 CORS。

生产启动使用编译后的 `build/server/index.js`，运行镜像只安装生产依赖。`npm start` 前需执行 `npm run build`；开发模式仍使用 `npm run dev`。域名、端口、TLS 与公网连通性需在实际云服务器验收。当前按用户要求不实现费用控制、套餐及订阅收费，这些不作为本次上线前置条件；已有文件和并发资源限制继续生效。

认证与网络边界的设计参考：[OWASP 会话管理](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html)、[OWASP SSRF 防护](https://cheatsheetseries.owasp.org/cheatsheets/Server_Side_Request_Forgery_Prevention_Cheat_Sheet.html)。

后端测试启动独立 HTTP 上游与临时数据库，验证协议、真实网络调用、并行/委派、顺序传递文件、调用预算、停止、持久化和凭据脱敏，以及管理员初始化、逐能力测试门槛、密钥登录、授权撤销、跨用户任务/附件/事件/导出隔离、上游配置隐藏和自接服务的内网访问限制；测试夹具不会出现在正式工作区。浏览器测试覆盖原工作台及新增后台与分发登录流程，使用 Playwright Chromium；没有浏览器时先运行 `npx playwright install chromium`。`test-results/` 为测试截图。

结构：`server/` 本机 API、加密存储、协议适配、媒体与协作/步骤引擎；`shared/` 公共类型；`src/` 单页界面；`tests/` 接口和浏览器测试。
